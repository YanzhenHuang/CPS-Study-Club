# CPU亲和（CPU Affinity）：进程与CPU核心的绑定机制

CPU亲和，又称**处理器亲和性**、**CPU绑定（CPU Pinning）** 或**缓存亲和性**，是操作系统中一种将**进程或线程绑定到指定CPU核心**上运行的机制，使它们仅在特定核心而非任意核心上执行。这是对对称多处理（SMP）系统中默认中央队列调度算法的修改。

---

### 一、核心概念：软亲和 vs 硬亲和

| 类型 | 定义 | 特点 | 操作系统行为 |
|------|------|------|--------------|
| **软亲和性（Soft Affinity）** | 进程"偏好"在特定核心运行，但调度器可灵活调整 | 非强制性，兼顾性能与负载均衡 | Linux默认行为：尽量让进程在最近运行过的核心上继续执行 |
| **硬亲和性（Hard Affinity）** | 强制进程只能在指定核心集合上运行 | 严格绑定，禁止跨核迁移 | 需通过系统调用或工具显式设置，调度器必须遵守 |

---

### 二、为什么需要CPU亲和？

1.  **提升缓存局部性**
    - 减少跨核迁移导致的**缓存失效**（L1/L2/L3缓存丢失）
    - 保持数据在核心私有缓存中，提高内存访问效率

2.  **降低调度开销**
    - 减少上下文切换次数与开销
    - 避免核心间状态同步成本

3.  **关键任务隔离**
    - 确保实时/低延迟应用（如金融交易、工业控制）获得稳定CPU资源
    - 防止关键进程被其他任务干扰

4.  **NUMA架构优化**
    - 绑定进程到其内存所在节点的CPU核心
    - 减少跨节点内存访问延迟，提升性能

---

### 三、实现方式与工具

#### 1. Linux系统
- **命令行工具**：`taskset`（设置进程CPU亲和掩码）
  ```bash
  # 查看进程1234的CPU亲和性
  taskset -p 1234
  
  # 将进程1234绑定到CPU 0和1
  taskset -cp 0,1 1234
  
  # 启动程序时绑定到CPU 2
  taskset -c 2 ./myprogram
  ```

- **系统调用**：`sched_setaffinity()` / `sched_getaffinity()`（C/C++编程）
  ```c
  #include <sched.h>
  cpu_set_t mask;
  CPU_ZERO(&mask);
  CPU_SET(0, &mask); // 绑定到CPU 0
  sched_setaffinity(0, sizeof(mask), &mask); // 0表示当前进程
  ```

#### 2. Windows系统
- **API函数**：`SetProcessAffinityMask()` / `SetThreadAffinityMask()`
- **任务管理器**：详细信息 → 右键进程 → 设置相关性

---

### 四、适用场景与注意事项

#### 适合使用CPU亲和的场景：
- **实时系统**：需要稳定低延迟的应用（如音频处理、工业自动化）
- **高并发服务器**：数据库、Web服务器等需要减少性能波动的服务
- **NUMA架构服务器**：多节点系统中优化内存访问
- **高性能计算**：科学计算、AI训练等需要最大化缓存利用率的场景

#### 不适合或需谨慎的场景：
- **负载变化剧烈的系统**：可能导致CPU资源浪费
- **单核或低核心数系统**：绑定意义不大，甚至影响性能
- **不了解系统架构时**：错误绑定可能导致性能下降

---

### 总结

CPU亲和是一种**性能优化技术**，通过控制进程与CPU核心的绑定关系，平衡缓存局部性与负载均衡，在特定场景下可显著提升系统性能与稳定性。它不是银弹，需根据系统架构、应用特性和负载情况合理使用。
