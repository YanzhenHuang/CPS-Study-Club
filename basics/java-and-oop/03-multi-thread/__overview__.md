# Java 多线程核心知识点大全（全细节展开版）
这份总结覆盖**基础、原理、API、锁、线程池、JUC、面试高频**，每个知识点都详细展开，适合系统学习和面试背诵。

## 一、基础核心概念
### 1. 进程 vs 线程
- **进程**：操作系统分配**内存、CPU、IO**等资源的最小单位，是独立运行的程序实例。每个进程有独立的虚拟地址空间，进程间通信成本高（管道、消息队列、Socket）。
- **线程**：CPU调度和执行的最小单位，依附于进程存在。**同一进程内的所有线程共享进程的堆、方法区资源**，仅独享栈、程序计数器，创建/销毁成本极低，通信更便捷。

### 2. 并发 vs 并行
- **并发**：单核CPU下，操作系统通过**时间片轮转**快速切换多个线程，宏观上看起来同时执行，微观上仍是串行执行。
- **并行**：多核CPU下，多个核心**真正同时执行**不同线程，是物理层面的同时运行。

### 3. 线程安全
多个线程同时访问**共享资源（变量、对象、方法）**时，无论线程如何切换、调度，无需额外同步控制，执行结果都符合预期，不会出现数据错乱、脏读、重复计算等问题，即为线程安全。

### 4. 临界区
多线程中会被**多个线程同时访问的代码块/共享资源区域**，临界区必须加同步控制，否则会引发线程安全问题。

## 二、线程的4种创建方式（详细展开）
### 1. 继承 `Thread` 类
- 实现方式：自定义类继承`Thread`，重写`run()`方法，调用`start()`启动线程。
- 特点：Java是**单继承**，若继承Thread则无法再继承其他类，扩展性差。
- 关键：`run()`是线程的业务逻辑方法，直接调用`run()`是普通方法执行，**只有`start()`会向JVM申请线程，真正启动新线程**。

### 2. 实现 `Runnable` 接口
- 实现方式：实现`Runnable`接口重写`run()`，将实例传入`Thread`构造器，调用`start()`。
- 特点：避免单继承局限，**无返回值**，无法抛出受检异常，适合无结果返回的异步任务。

### 3. 实现 `Callable` 接口（JDK1.5+）
- 实现方式：实现`Callable`重写`call()`，配合`FutureTask`包装，传入`Thread`启动，通过`Future.get()`获取返回值。
- 特点：**支持返回值**、**支持抛出受检异常**，解决了Runnable的缺陷，`get()`方法会阻塞直到线程执行完毕。

### 4. 线程池创建（开发最优方案）
- 实现方式：通过`ThreadPoolExecutor`或`ExecutorService`创建线程池，提交任务执行。
- 特点：**复用线程**，避免频繁创建/销毁线程的开销；统一管理线程数量、任务队列，防止资源耗尽，生产环境强制使用。

## 三、线程生命周期（6大状态+切换逻辑）
Java线程共6种状态，定义在`Thread.State`枚举中，状态不可跳跃：
1. **NEW（新建）**
   用`new Thread()`创建线程对象，但**未调用`start()`**，线程未被JVM调度。
2. **RUNNABLE（可运行）**
   调用`start()`后进入该状态，包含**就绪（Ready）**和**运行中（Running）**：就绪是等待CPU时间片，运行中是正在执行`run()`。
3. **BLOCKED（阻塞）**
   线程**等待获取synchronized隐式锁**时进入该状态，拿到锁后立即回到RUNNABLE。
4. **WAITING（无限等待）**
   线程主动调用`wait()`、`join()`、`LockSupport.park()`后进入，**不会自动唤醒**，需其他线程调用`notify()`/`notifyAll()`或中断唤醒，唤醒后回到RUNNABLE。
5. **TIMED_WAITING（限时等待）**
   调用`sleep(long)`、`wait(long)`、`join(long)`、`parkNanos()`进入，**超时自动唤醒**，无需外部干预。
6. **TERMINATED（终止）**
   线程`run()`执行完毕、抛出未捕获异常终止，或手动停止后进入该状态，线程生命周期结束。

## 四、线程核心方法（用法+区别+细节）
### 1. `sleep(long millis)`
- 作用：让当前线程休眠指定毫秒数，**主动让出CPU**。
- 关键特性：**不会释放持有的锁**，休眠期间其他线程无法获取锁，休眠结束后回到就绪态。

### 2. `yield()`
- 作用：线程主动礼让CPU，从运行态回到**就绪态**，不进入阻塞。
- 特点：礼让后CPU可能再次调度该线程，无法保证礼让效果，仅用于优化线程调度。

### 3. `join()`/`join(long)`
- 作用：在当前线程中调用其他线程的`join()`，**当前线程会阻塞**，直到被调用的线程执行完毕/超时。
- 场景：主线程等待子线程执行完再继续，实现线程串行执行。

### 4. `wait()`/`notify()`/`notifyAll()`
- 作用：线程等待/唤醒，**必须在synchronized同步块/方法中使用**。
- 关键特性：调用`wait()`会**立即释放锁**，线程进入WAITING；`notify()`随机唤醒一个等待线程，`notifyAll()`唤醒所有等待线程。

### 5. `interrupt()`/`isInterrupted()`/`interrupted()`
- `interrupt()`：给线程打**中断标记**，不是强制停止线程，线程可自行判断标记决定是否终止。
- `isInterrupted()`：判断线程是否有中断标记，**不清除标记**。
- `interrupted()`：静态方法，判断并**清除中断标记**。

### 6. `Thread.currentThread()`
- 静态方法，获取当前执行代码的线程对象，是线程操作的基础方法。

## 五、线程安全同步机制（锁核心）
### 1. `synchronized` 隐式内置锁
JVM层面实现的悲观锁，自动加锁/释放锁，核心用法：
- 修饰**实例方法**：锁当前对象（this），同一对象的多线程竞争同一把锁。
- 修饰**静态方法**：锁类的Class对象，全局唯一锁，所有实例共享。
- 修饰**同步代码块**：锁指定对象（自定义锁粒度，更灵活）。
- 核心特性：**可重入**（同一线程可重复获取锁，避免死锁）、**非公平锁**、**独占锁**、**悲观锁**。

### 2. `Lock` 显式锁（JDK1.5+，`java.util.concurrent.locks`）
基于API实现的锁，手动加锁/释放锁，核心实现类`ReentrantLock`：
- 核心方法：`lock()`（加锁）、`unlock()`（释放锁，必须在finally中，防止死锁）、`tryLock()`（尝试获取锁，失败不阻塞）。
- 扩展能力：支持**公平锁/非公平锁**、**可中断锁**、**超时获取锁**、`Condition`精准唤醒线程。
- 适用场景：需要灵活锁控制的复杂并发场景。

### 3. `synchronized` vs `ReentrantLock` 详细区别
- 实现层面：synchronized是JVM原生实现，Lock是Java API实现。
- 锁释放：synchronized自动释放（代码执行完/异常），Lock必须手动`unlock()`。
- 灵活性：Lock支持公平锁、中断、超时、多Condition，synchronized无。
- 性能：JDK1.6后synchronized锁优化，高并发下性能与Lock接近。

## 六、线程间通信（线程协作方式）
### 1. `wait/notify/notifyAll`
- 配合synchronized使用，是传统线程通信方式，缺点是唤醒随机，无法精准指定线程。
- 场景：生产者-消费者模型基础实现。

### 2. `Lock + Condition`
- `Condition`是Lock的等待/唤醒组件，`await()`对应wait，`signal()`/`signalAll()`对应notify。
- 优势：**一个Lock可绑定多个Condition**，实现精准唤醒（如生产者唤醒消费者，消费者唤醒生产者）。

### 3. 共享变量 + `volatile`
- 用volatile修饰共享状态变量，保证变量可见性，实现简单的线程状态通知（如线程停止标记）。
- 局限：仅适用于无复杂计算的状态传递，不保证原子性。

### 4. 管道流（PipedInputStream/PipedOutputStream）
- 基于IO流实现线程间**字节/字符数据传输**，适用于线程间大量数据传递，日常开发极少使用。

## 七、线程池（生产核心，必掌握）
### 1. `ThreadPoolExecutor` 7大核心参数（逐行详解）
```java
new ThreadPoolExecutor(
    corePoolSize,    // 核心线程数：线程池常驻线程，不会被回收（默认）
    maximumPoolSize, // 最大线程数：线程池能创建的最大线程数量
    keepAliveTime,   // 空闲线程存活时间：非核心线程空闲超过该时间会被回收
    unit,            // 存活时间单位
    workQueue,       // 阻塞队列：存储等待执行的任务
    threadFactory,   // 线程工厂：自定义线程名称、优先级、守护线程
    handler          // 拒绝策略：任务超出线程池承载能力时的处理方式
);
```

### 2. 线程池工作流程
1. 任务提交后，优先创建**核心线程**执行任务；
2. 核心线程满了，任务进入**阻塞队列**排队；
3. 队列满了，创建**非核心线程**执行任务；
4. 总线程数达到最大线程数，触发**拒绝策略**。

### 3. 4种拒绝策略
- `AbortPolicy`：默认策略，直接抛出`RejectedExecutionException`，阻止系统运行。
- `CallerRunsPolicy`：任务回退给**提交任务的线程**执行，降低提交速度。
- `DiscardPolicy`：直接丢弃当前任务，不抛异常，无感知。
- `DiscardOldestPolicy`：丢弃队列中**最早的任务**，重新提交当前任务。

### 4. `Executors` 工具类创建的4种线程池（生产禁用）
- `newFixedThreadPool`：固定线程数，队列无界，会导致OOM。
- `newCachedThreadPool`：最大线程数无界，会创建大量线程耗尽资源。
- `newSingleThreadExecutor`：单线程，队列无界，OOM风险。
- `newScheduledThreadPool`：定时任务线程池，队列无界。
- 生产规范：**手动创建ThreadPoolExecutor**，自定义参数避免OOM。

## 八、JUC 并发工具类（`java.util.concurrent`）
### 1. `CountDownLatch` 倒计时门栓
- 原理：初始化一个计数器，线程调用`countDown()`计数器-1，调用`await()`的线程会阻塞直到计数器为0。
- 场景：主线程等待多个子线程执行完毕再执行。

### 2. `CyclicBarrier` 循环栅栏
- 原理：设置屏障数，线程调用`await()`到达屏障后阻塞，直到所有线程都到达屏障，再一起执行。
- 特点：**可循环使用**，支持回调任务，场景：多线程计算后汇总结果。

### 3. `Semaphore` 信号量
- 原理：初始化许可数，线程调用`acquire()`获取许可，`release()`释放许可，无许可则阻塞。
- 场景：**控制并发线程数**（如接口限流、数据库连接池控制）。

### 4. `Exchanger` 交换器
- 原理：两个线程到达交换点时，互相交换数据，仅适用于双线程数据传递。

### 5. `Phaser` 阶段器
- 升级版CyclicBarrier+CountDownLatch，支持动态调整线程数、分阶段执行，复杂并发协作场景使用。

---

## 九、Java 内存模型（JMM）
JMM是JVM定义的**线程内存规范**，解决多线程下可见性、原子性、有序性问题：
1. **主内存**：存储共享变量（堆、方法区），所有线程共享。
2. **工作内存**：每个线程独享，存储主内存变量的副本，线程操作变量先读写工作内存，再同步回主内存。

### JMM三大核心特性
1. **原子性**：一个操作不可分割、不可中断，要么全部执行，要么不执行。synchronized、Lock、CAS保证原子性。
2. **可见性**：一个线程修改共享变量，其他线程能立即感知最新值。synchronized、Lock、volatile保证可见性。
3. **有序性**：禁止CPU/编译器的**指令重排序**，保证代码执行顺序符合预期。synchronized、Lock、volatile保证有序性。

## 十、`volatile` 关键字（轻量级同步）
### 1. 核心作用
- **保证可见性**：线程修改volatile变量，立即同步回主内存；其他线程读取时，直接从主内存拉取最新值，不使用工作内存副本。
- **禁止指令重排序**：通过**内存屏障**实现，防止CPU优化打乱指令顺序（如DCL单例的对象半初始化问题）。

### 2. 关键缺陷
**不保证原子性**：仅对单次读/写有效，复合操作（如`i++`，读+改+写三步）无法保证原子性，多线程下仍会线程不安全。

### 3. 适用场景
- 线程状态标记（如停止线程标记）；
- 双重校验锁（DCL）单例模式；
- 无需原子性的共享变量读写。

---

## 十一、CAS 与 原子类
### 1. CAS（Compare And Swap）比较并交换
- 原理：无锁乐观锁，包含**内存值V、预期值A、新值B**，若V==A则将V更新为B，否则重试，全程无锁，CPU原语支持，原子性操作。
- 优点：无锁竞争，高并发下性能优于悲观锁。
- 缺点：循环自旋消耗CPU；存在**ABA问题**。

### 2. ABA 问题
线程1读取变量值为A，线程2将A改为B再改回A，线程1执行CAS时认为值未变，成功更新，导致逻辑错误。
- 解决：`AtomicStampedReference`（带版本号的原子引用），通过版本号判断变量是否被修改。

### 3. JUC原子类
- 基本类型：`AtomicInteger`、`AtomicLong`、`AtomicBoolean`；
- 引用类型：`AtomicReference`；
- 高并发优化：`LongAdder`（分段累加，高并发下性能远超AtomicLong）。

---

## 十二、AQS 抽象队列同步器
### 1. 核心定义
`AbstractQueuedSynchronizer`，JUC锁和工具类的**底层核心框架**，ReentrantLock、CountDownLatch、Semaphore均基于AQS实现。

### 2. 核心组件
- **state变量**：同步状态，int类型，0表示无锁，≥1表示加锁（可重入则累加）；
- **CLH双向队列**：存储等待锁的线程，公平排队，避免线程饥饿。

### 3. 工作原理
线程尝试获取锁失败后，加入CLH队列阻塞；锁释放后，唤醒队列头节点线程尝试获取锁，全程基于CAS+自旋实现。

---

## 十三、`ThreadLocal` 线程本地变量
### 1. 核心作用
为每个线程创建**独立的变量副本**，线程间互不干扰，实现线程隔离，解决多线程共享变量的安全问题。

### 2. 底层原理
每个`Thread`对象内部维护`ThreadLocalMap`，key为`ThreadLocal`实例，value为线程副本变量。

### 3. 内存泄漏问题
- 线程池中的线程复用，`ThreadLocalMap`的key是弱引用，value是强引用，线程不销毁会导致value无法回收，引发内存泄漏。
- 解决方案：使用完`ThreadLocal`后，**手动调用`remove()`方法清除变量**。

---

## 十四、死锁
### 1. 死锁的4个必要条件（缺一不可）
1. **互斥条件**：资源同一时间只能被一个线程持有；
2. **请求与保持**：线程持有资源的同时，又请求其他线程的资源；
3. **不可剥夺条件**：线程持有的资源只能自己释放，无法被强制剥夺；
4. **循环等待条件**：多个线程形成资源等待闭环（A等B，B等A）。

### 2. 死锁避免/解决方法
- 破坏循环等待：**统一加锁顺序**，所有线程按固定顺序获取锁；
- 破坏请求与保持：一次性申请所有资源；
- 使用定时锁：`tryLock(timeout)`，超时放弃锁，避免无限等待；
- 死锁检测：通过JDK工具（jstack、jconsole）检测死锁，手动干预。

---

## 十五、线程安全集合
### 1. 传统安全集合（低效，已淘汰）
- `Vector`、`Hashtable`：全程加synchronized，锁粒度大，并发性能极差。

### 2. JUC 高性能安全集合
- `CopyOnWriteArrayList`：写时复制，写操作加锁复制数组，读操作无锁，适合**读多写少**场景；
- `CopyOnWriteArraySet`：底层基于CopyOnWriteArrayList实现；
- `ConcurrentHashMap`：JDK1.7分段锁，JDK1.8+**CAS+synchronized+红黑树**，锁粒度极小，并发性能极高；
- `ConcurrentSkipListMap`：有序的线程安全Map，替代TreeMap。

## 十六、JVM 锁优化（JDK1.6+）
JVM对synchronized做了大量优化，提升锁性能：
1. **锁升级**：无锁 → 偏向锁 → 轻量级锁 → 重量级锁（不可逆）
   - 偏向锁：默认锁，标记持有线程，无竞争时直接获取锁；
   - 轻量级锁：竞争出现，CAS自旋获取锁，不阻塞线程；
   - 重量级锁：自旋失败，线程阻塞，升级为OS互斥锁。
2. **锁消除**：JVM检测到代码无共享资源竞争，自动删除锁。
3. **锁粗化**：将多次连续的加锁/解锁合并为一次，减少锁开销。
4. **自旋锁**：线程不阻塞，循环CAS尝试获取锁，避免线程切换开销。
5. **自适应自旋**：JVM根据历史自旋成功率，动态调整自旋次数。

## 十七、高频面试核心问答（展开版）
1. **start()和run()的区别**
   start()是启动线程，向JVM申请线程资源，触发线程调度；run()是线程的业务方法，直接调用是普通方法，不会创建新线程。

2. **sleep()和wait()的区别**
   sleep()是Thread方法，不释放锁，自动唤醒；wait()是Object方法，必须在同步块中，释放锁，需手动唤醒。

3. **为什么volatile不保证原子性？**
   volatile只保证单次读写的可见性和有序性，复合操作（i++）是多步指令，多线程下会出现指令交错，无法保证原子性。

4. **线程池为什么不允许用Executors创建？**
   Executors创建的线程池队列无界或最大线程数无界，高并发下会堆积大量任务/线程，导致OOM内存溢出。

5. **CAS的ABA问题怎么解决？**
   使用AtomicStampedReference，给变量加版本号，每次修改变量同时更新版本号，通过版本号判断变量是否被篡改。
