# JVM、JRE、JDK 层级关系全解

JVM -- (+类库) --> JRE -- (+运行环境 +开发工具) --> JDK

---

## 一、先逐个拆解核心概念
### 1. JVM（Java Virtual Machine）：Java 虚拟机
**层级定位：最底层、核心运行载体**
- 本质：一个**虚拟的计算机系统**，有自己的指令集、内存模型、垃圾回收机制。
- 核心作用：**只负责加载并执行 `.class` 字节码文件**，不认识 `.java` 源码。
- 跨平台关键：
  Windows、Linux、macOS 各有专属版本的 JVM，但所有 JVM 都能识别统一的 Java 字节码 → 实现「一次编译，到处运行」。
- 内部层级：类加载子系统 → 运行时数据区（堆、栈、方法区等）→ 执行引擎 → 本地方法接口，是纯运行层面的核心。

> 总结：JVM 是**运行 Java 程序的最小单元**，没有它，字节码根本跑不起来。

### 2. JRE（Java Runtime Environment）：Java 运行时环境
**层级定位：中间层，完整运行环境**
- 构成：**JVM + Java 核心类库 + 运行时支持文件**
- 核心类库：`java.lang`、`java.util`、`java.io` 等 Java 自带基础工具类，是写 Java 代码依赖的底层API。
- 作用：**仅能运行已编译好的 Java 程序**，**不能开发、不能编译源码**。
- 适用人群：普通电脑用户（只需要跑 Java 软件，不用写代码）。

> 总结：JRE = 能跑 Java 程序的完整环境，比 JVM 多了「运行必需的类库」。

### 3. JDK（Java Development Kit）：Java 开发工具包
**层级定位：最上层，开发+运行全套工具**
- 构成：**JRE + 开发工具集**
- 开发工具集：
  - `javac`：源码编译器（把 `.java` 编译成 `.class`）
  - `java`：启动 JVM 运行程序
  - `jar`：打包工具
  - `jdb`：调试工具
  - `jvisualvm`：JVM 监控工具
  - `javadoc`：文档生成工具
- 作用：**既能编写、编译 Java 源码，又能运行 Java 程序**。
- 适用人群：Java 开发者（必须装 JDK，仅装 JRE 无法开发）。

> 总结：JDK 是开发 Java 的全套工具箱，包含了运行环境和开发工具。

---

## 二、严格的层级包含关系
从**范围大小/层级上下**看，是完全的包含关系：
```
JDK ＞ JRE ＞ JVM
```
拆解公式：
1. **JDK = 开发工具 + JRE**
2. **JRE = JVM + 核心类库 + 运行支持组件**
3. **JVM = 字节码执行引擎 + 内存管理 + 垃圾回收**

用通俗比喻：
- JVM = 汽车发动机（只负责驱动）
- JRE = 整车（发动机+车身+轮胎，能开但不能造）
- JDK = 汽车制造厂+整车（能造车，也能开车）

## 三、从代码到运行：完整层级流程
这是最直观理解层级协作的方式，按**上层开发 → 中层编译 → 底层运行**的顺序：

1. **上层（JDK 开发层）**
   开发者用编辑器写 `.java` 源码文件。

2. **编译层（JDK 工具层）**
   调用 JDK 里的 `javac` 编译器，把 `.java` 编译成 **`.class` 字节码文件**。
   （这一步只有 JDK 能做，JRE/JVM 都做不到）

3. **运行层（JRE 环境层）**
   执行 `java` 命令，启动 JRE 环境：
   - JRE 加载核心类库
   - 调用底层 JVM

4. **最底层（JVM 执行层）**
   JVM 加载 `.class` 字节码，校验、解析、执行，最终对接操作系统/硬件，完成程序运行。

## 四、层级对比表（一目了然）
| 组件 | 层级 | 核心构成 | 能力 | 适用对象 |
|------|------|----------|------|----------|
| JVM | 底层 | 执行引擎、内存管理、GC | 仅执行字节码 | 无（不能单独使用） |
| JRE | 中间层 | JVM + 核心类库 | 仅运行Java程序 | 普通用户 |
| JDK | 上层 | JRE + 编译/调试/打包工具 | 开发+编译+运行Java程序 | Java开发者 |

## 五、常见误区澄清
1. **装了 JDK 就不用装 JRE/JVM？**
   是的。JDK 内置完整 JRE，JRE 内置 JVM，装 JDK 后三者都有。
2. **JVM 是跨平台的，字节码也是？**
   字节码是跨平台的；**JVM 不跨平台**（Windows JVM 不能在 Linux 用）。
3. **只有 Java 语言能跑在 JVM 上？**
   不是。Kotlin、Scala、Groovy 等 JVM 语言，编译后都是字节码，都能由 JVM 执行。
4. **JVM 属于 JDK 的一部分吗？**
   间接属于。JDK 包含 JRE，JRE 包含 JVM，所以 JVM 是 JDK 的底层核心组件。
