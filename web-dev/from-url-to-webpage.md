## 1. URL 解析与预处理 (URL Parsing & Pre-check)
当用户按下回车键后，浏览器首先处理输入的字符串。

*   **判断输入内容：** 浏览器判断输入的是搜索关键词还是合法的 URL。如果是关键词，会使用默认搜索引擎拼接成 URL。
*   **协议检查：** 检查是否有协议头（如 `http://` 或 `https://`）。如果没有，浏览器会根据配置自动补全（通常默认为 HTTPS）。
*   **HSTS 检查：** 如果该域名在浏览器的 HSTS (HTTP Strict Transport Security) 列表中，浏览器会强制将 HTTP 请求转换为 HTTPS。
*   **缓存检查：** 浏览器会先检查本地是否有该域名的 DNS 缓存。如果有且未过期，直接使用，跳过 DNS 查询。

## 2. DNS 域名解析 (DNS Resolution)
浏览器需要知道域名对应的 **IP 地址** 才能发起网络请求。解析顺序如下：

1.  **浏览器缓存：** 检查浏览器自身的 DNS 缓存。
2.  **操作系统缓存：** 检查本地 hosts 文件或系统 DNS 缓存。
3.  **路由器缓存：** 请求发送到路由器，检查路由器缓存。
4.  **ISP DNS 服务器：** 如果本地都没有，请求发送给互联网服务提供商（ISP）的 DNS 服务器。
5.  **递归/迭代查询：** 如果 ISP DNS 也没有，它会向根域名服务器、顶级域名服务器（如 .com）、权威域名服务器发起查询，最终获取到 IP 地址。
6.  **返回结果：** 获取到 IP 后，层层返回给浏览器，并本地缓存。

## 3. 建立网络连接 (TCP/TLS Handshake)
拿到 IP 地址后，浏览器需要与服务器建立连接。

*   **TCP 三次握手 (建立连接)：**
    1.  **SYN:** 客户端发送 SYN 包，请求建立连接。
    2.  **SYN-ACK:** 服务器收到后，回复 SYN-ACK 包，确认收到并同意连接。
    3.  **ACK:** 客户端回复 ACK 包，连接建立。
*   **TLS 握手 (如果是 HTTPS)：**
    *   在 TCP 连接建立后，进行 TLS 握手以加密通信。
    *   协商加密算法、验证服务器证书（CA 认证）、交换密钥（生成会话密钥）。
    *   *注：HTTP/2 和 HTTP/3 在此阶段会有优化，如 TLS 1.3 减少了握手次数。*

## 4. 发送 HTTP 请求 (Send HTTP Request)
连接建立后，浏览器构建并发送 HTTP 请求报文。

*   **请求行：** 包含方法（GET/POST）、URL 路径、HTTP 版本。
*   **请求头 (Headers)：** 包含用户代理 (User-Agent)、Cookie、Accept 类型、Host 等信息。
*   **请求体 (Body)：** 如果是 POST 请求，包含表单数据或 JSON 数据。

## 5. 服务器处理请求 (Server Processing)
请求到达服务器端（可能是 Nginx、Apache 等反向代理），处理流程如下：

1.  **负载均衡：** 如果部署了集群，负载均衡器将请求分发给具体的应用服务器。
2.  **后端逻辑：** 应用服务器（如 Node.js, Java, Python, Go）接收请求，解析参数。
3.  **数据交互：** 后端可能需要查询数据库 (MySQL)、缓存 (Redis) 或调用第三方 API。
4.  **生成响应：** 服务器根据逻辑生成 HTML 内容，或返回 JSON 数据，或返回文件流。
5.  **返回状态码：** 如 200 (成功), 301/302 (重定向), 404 (未找到), 500 (服务器错误)。

## 6. 接收响应与浏览器渲染 (Rendering)
浏览器收到 HTTP 响应后，开始解析和渲染页面。这是前端性能优化的关键点。

1.  **解析 HTML：** 构建 **DOM 树** (Document Object Model)。
2.  **解析 CSS：** 构建 **CSSOM 树** (CSS Object Model)。
3.  **执行 JavaScript：** 遇到 `<script>` 标签时，可能会阻塞 DOM 构建（除非有 `async` 或 `defer`）。JS 可以修改 DOM 和 CSSOM。
4.  **构建渲染树 (Render Tree)：** 将 DOM 和 CSSOM 合并，排除不显示的元素（如 `display: none`）。
5.  **布局 (Layout/Reflow)：** 计算每个节点在屏幕上的确切位置和大小。
6.  **绘制 (Paint)：** 将节点转换为屏幕上的实际像素（填充颜色、文本、边框等）。
7.  **合成 (Composite)：** 将不同的图层合成在一起，最终显示在屏幕上。

*在此过程中，浏览器还会解析 HTML 中的其他资源链接（如图片、CSS、JS），并重复上述 **DNS -> TCP -> HTTP** 流程去获取这些资源（通常利用并发连接或 HTTP/2 多路复用）。*

## 7. 连接断开 (Connection Termination)
*   **TCP 四次挥手：** 当数据传输完成，客户端或服务器发起关闭连接请求。
*   **Keep-Alive：** 现代浏览器和服务器通常默认开启 `Keep-Alive`，在一个 TCP 连接上发送多个 HTTP 请求，避免频繁握手断开，提高性能。只有在超时或明确关闭时才会断开。

## 流程图总结 (简化版)

```text
用户输入 URL
   ↓
浏览器解析 URL & 检查 HSTS/缓存
   ↓
DNS 解析 (获取 IP 地址)
   ↓
TCP 三次握手 (建立连接)
   ↓
TLS 握手 (如果是 HTTPS，建立加密)
   ↓
发送 HTTP 请求
   ↓
服务器处理 (负载均衡 -> 后端逻辑 -> 数据库)
   ↓
返回 HTTP 响应 (HTML/CSS/JS/图片)
   ↓
浏览器渲染 (DOM -> CSSOM -> Render Tree -> Layout -> Paint)
   ↓
页面展示 & 资源加载 (重复上述网络请求)
   ↓
TCP 断开 (或保持 Keep-Alive)
```
